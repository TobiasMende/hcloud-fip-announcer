# hcloud-fip-announcer v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Kubernetes controller that keeps Hetzner Cloud Floating IPs on a node with ready endpoints for the LoadBalancer Services of its class, moves them on cordon and on failure, and ships as a signed image plus Helm chart.

**Architecture:** controller-runtime manager with leader election. A `FloatingIPGroup` reconciler owns the Hetzner FIP lifecycle and placement; a Service reconciler writes the group's addresses into Services of the configured `loadBalancerClass`. Pure packages decide eligibility and placement; a prober feeds node health into the group reconciler through a channel source. Hetzner access sits behind an interface with a fake for tests.

**Tech Stack:** Go (version from the kubebuilder v4 scaffold), controller-runtime, kubebuilder v4, `github.com/hetznercloud/hcloud-go/v2`, envtest, Helm 3, GitHub Actions, ko or Docker buildx, cosign, syft, Renovate.

**Spec:** `docs/design.md`

## Global Constraints

- Everything in English: code, comments, docs, commit messages, chart.
- License Apache-2.0; module `github.com/TobiasMende/hcloud-fip-announcer`.
- API group `fip-announcer.inocea.de`, version `v1alpha1`, kind `FloatingIPGroup`, cluster-scoped (builder's call per spec "Left to the builder", recorded here).
- Default `loadBalancerClass`: `fip-announcer.inocea.de/floating-ip`; flag `--load-balancer-class`, empty string means "Services without a class".
- Annotations: `fip-announcer.inocea.de/group` (group name), `fip-announcer.inocea.de/health-check` (`http://:<port><path>` or `tcp://:<port>`).
- Hetzner labels on managed FIPs: `fip-announcer.inocea.de/cluster-id`, `fip-announcer.inocea.de/group`.
- Required flag `--cluster-id`; Hetzner token from env `HCLOUD_TOKEN`.
- Defaults: probe interval 1 s, failure threshold 3, anti-flap 30 s, Hetzner poll 30 s, lease 6 s / renew 4 s / retry 1 s, IPv6 address `::1` of the /64.
- Probes never call the Hetzner API. Hetzner budget: ≤ 3600 requests/h per project.
- Never assign a FIP to an ineligible node; never delete a FIP unless `deletionPolicy: Delete`; never take a FIP assigned to a non-cluster server.
- Images: `ghcr.io/tobiasmende/hcloud-fip-announcer`, linux/amd64 + linux/arm64, non-root, read-only root filesystem.

## Review Focus

1. Controller restart or leader change while a FIP is assigned → adopt the current Hetzner holder, no move if it is eligible (test in Task 8).
2. Hetzner API error or rate limit during a move → no partial state recorded, retry with backoff, `status.node` unchanged until the assignment succeeds (Task 8).
3. Two Services in one group with ready endpoints on disjoint nodes → group `Degraded`, FIP stays (Task 5).
4. Service requests IPv6 (`ipFamilies` contains IPv6) but the group is IPv4-only → status gets only IPv4, Warning event on the Service (Task 7).
5. Holder's Hetzner server deleted or powered off → immediate move, anti-flap skipped (Task 6).
